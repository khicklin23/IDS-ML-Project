report.json top-level keys: report_version, schema_version, generated_at, run_id, dataset (manifest + split_sizes + sample_flows -- each a flow record with src_ip/dst_ip and other IDS-analyst-style fields, not raw host ids), binary_model (train_config, history, test_metrics, rule_baseline_metrics -- same metric shape for both so a model-vs-rule comparison is trivial), multiclass_model (class_names, train_config, history, test_metrics with per_class precision/recall/f1/support plus a full confusion_matrix -- this is the attack-type mapping capability), alerts (total, by_severity, sample -- each alert has both scenario_ground_truth and the model's own predicted_scenario/predicted_scenario_confidence, kept as separate fields on purpose), artifact_paths (where the raw dataset/model/alerts files live if you need more than the embedded sample).

SCOPE: single-page static dashboard (HTML/CSS/JS, or a static-export framework of your choice) built against report.json, deployable to Vercel with no backend server at runtime. Exact visual design is open -- dark command-center direction from docs/PRODUCT_VISION.md still applies, but layout is now ONE page, not six.
