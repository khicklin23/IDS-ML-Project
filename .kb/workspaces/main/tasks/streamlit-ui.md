### User-reported "blank page, spinning icons" -- found and fixed, 2026-10-10

The user actually tried it and the real `st.navigation` entry point (`Home.py`) had never been directly exercised before (my `AppTest` verification used a custom router script that called each page's `render()` directly, bypassing `st.Page`/`st.navigation` entirely -- a real gap). Running `AppTest.from_file("src/ids_ml/app/Home.py")` directly surfaced it. Three things, in the order found:

1. **Not actually a hang**: the first script run legitimately takes **30-40+ seconds** on this machine's WSL/9p-mounted filesystem, almost entirely `import torch` (confirmed ~17s alone) plus sklearn/pandas. Confirmed via direct timing, and confirmed it is NOT a deadlock by giving it a long enough timeout (it completes). This explains the "blank + spinning icon" look: that's what a Streamlit app looks like *while the script is still importing*, before it has emitted any elements. Nothing to fix here beyond setting expectations -- subsequent reruns in the same server process are fast since imports are cached.
2. **Real bug**: `st.Page(..., icon=":satellite:")` (and 5 others) used GitHub/Slack-style emoji *shortcodes*, which `st.Page`'s `icon` param does not support (`StreamlitAPIException: Emoji shortcodes are not supported`). This exception happened *after* the ~40s import wait, so it likely did render as a visible error -- but only after a long, easy-to-miss delay. Fixed: switched to literal emoji characters.
3. **Real bug**: every page module's function is named `render`, and `st.Page` infers the URL path from the callable name when `url_path` isn't given -- so all six collided (`StreamlitAPIException: Multiple Pages specified with URL pathname render`). Fixed: added an explicit unique `url_path` to each `st.Page(...)` call in `Home.py`.

Re-verified `AppTest.from_file("src/ids_ml/app/Home.py")` end to end after both fixes: loads clean in ~40s, default page (Operations Overview) renders its title/caption/info box correctly, zero exceptions. 60/60 project tests still pass. `AppTest.switch_page()` itself doesn't cleanly support function-based (non-file) pages in this Streamlit version -- that's a test-harness limitation, not an app bug; page content/logic across the full pipeline was already verified via the router-script approach in the entry above.

**Takeaway for future UI work in this repo**: always run `AppTest.from_file()` against the *actual* entry point (`Home.py`), not a workaround script, and give it a long timeout (60-90s) on this filesystem before concluding something hung.
