Examples give the model something to learn

Python generates flow records and records which scenario produced them. The model sees the measurements. The correct label is kept separately and used to check its answer during training.

TRAINING

Predict, check, adjust

1

Predict

A batch of examples goes through the network. Its current weights produce a guess for each flow.

2

Measure the error

A loss function compares those guesses with the correct labels. Confident wrong guesses receive a larger penalty.

3

Adjust the connections

Backpropagation (working backward through the network to figure out which connections contributed to the mistake) calculates which weights contributed to the error. Adam (a popular, efficient way of applying those corrections) makes small updates to them.

4

Check on other examples

Validation data guides when to stop. A separate test set is used to report performance.

Steps 1–3 repeat across training batches. Validation is checked after each pass through the training set.
Training settings in this saved run

Dropout (randomly switching off a portion of neurons for one training step, so the network can’t lean on any single one too much) temporarily omits some hidden activations during training. Early stopping restores the checkpoint (a saved snapshot of the model from partway through training) with the lowest validation loss. Neither changes the examples’ ground-truth labels.

WEIGHTS

Connections learn; class weights balance

Learned connection weights

A weight controls how strongly an input affects a neuron. Positive and negative weights can reinforce or offset each other. Training learns many of these connections together.

Teaching example · one neuron, not the trained detector

ReLU keeps positive results and turns negative results into zero. This example produces a hidden activation, not an attack probability. Actual trained weights are not exposed in report.json.

Class weights in the loss

Normal traffic is more common than some attack families. Without balancing, the network could do well on the common class while ignoring rare ones.

The multiclass loss (the "how wrong was I" number training tries to shrink) weights rarer classes more heavily than common ones, so a family with few examples isn’t ignored just because it’s outnumbered. The binary loss balances suspicious examples against normal ones the same way.

A class weight changes training emphasis. It does not mean that a rare attack is more severe, and it does not set a manual “importance” for an input feature.

The distinction in equations

Neuron: ReLU(Σ input × learned weight + bias)

Multiclass loss weight ∝ 1 / training class count

Class weights are normalized in the implementation. They affect the error being optimized; the optimizer learns the connection weights.

PREDICTIONS

Two answers, from two separate networks

BINARY DETECTOR

“Should this flow be flagged?”

Its output is converted to a suspiciousness score. A threshold makes the flagging decision.

Normal
Suspicious
0.01.0

MULTICLASS CLASSIFIER

“Which behavior does it resemble?”

It produces one score per class. Softmax converts them into values that add up to one; the highest value supplies the family prediction.

These networks can disagree. The binary model triggers an alert; the multiclass model adds a family guess. A benign family prediction does not currently cancel a binary alert.

What the result does—and doesn’t—tell us

Check mistakes, not just accuracy

Precision asks how many flagged flows were actually suspicious. Recall asks how many suspicious flows were caught. False positives and misses matter alongside the overall score.

Whole sessions are kept in one split. This helps avoid evaluating on near-duplicate flows from the same episode the model trained on.

Behavior recognition has limits

A per-flow network learns combinations of measurements. It does not read an attacker’s intent, discover software vulnerabilities, or automatically recognize every new attack.

Severity buckets and incident grouping are deterministic backend steps. Confidence is a model output, not a guarantee. Synthetic results describe this generated experiment.
