Why give the model memory?

A single connection shows what happened once. Memory lets a model follow related connections and recognize a pattern in their order.

What changed, and why

The early Betas judge connections individually; Beta 3 adds sequence memory, and Sona combines that memory with broader attack training. These changes let the model learn relationships across events while retaining coverage of slower attacks.

INSIDE THE NETWORK

How Sona connects the dots

The Betas ask, “Does this connection look suspicious?” Sona can also ask, “What does this connection mean after the ones that came before it?” Its memory turns a series of individual measurements into a session-level prediction.

1. From measurements to neurons

An artificial neuron takes numbers, multiplies them by learned weights, adds a bias, and applies a mathematical function. Connection measurements become patterns of numerical activity. Training adjusts those weights so useful patterns influence the prediction.

Beta 1 and 2 use a multilayer perceptron (MLP): two processing layers with 32 and 16 units. Each connection receives its own prediction. Session voting combines the answers, but discards the relationships between earlier and later connections.

2. A small, evolving memory

Sona uses a gated recurrent unit (GRU). “Recurrent” means the same learned computation runs for each connection, using both the new measurements and the previous memory. Its hidden state is a vector of 32 numbers: a compressed summary that changes as the session unfolds.

These units work together. One is not a dedicated “scan neuron” or “beacon neuron”; evidence can be distributed across many units. The memory is learned numerical activity, not a list of stored connections.

3. Gates decide what carries forward

An update gate learns how much old memory to retain and how much new information to mix in. A reset gate controls how much previous memory contributes to a proposed new state. Each gate produces values between zero and one, like adjustable valves rather than on/off switches.

The gates are learned from examples, not manually written security rules. After the final connection, a classification layer maps the 32 memory values to six categories: benign traffic or one of five attack families.

4. Timing means relationships over time

The sequence-timing score tests whether a model can distinguish two sessions with the same connection measurements arranged into different patterns. The Betas give those sessions the same vote. Sona can update its memory differently as each pattern unfolds.

It measures recognition accuracy, not inference speed. It demonstrates a learned temporal capability on constructed examples; timing rules or engineered sequence features can also use this information.

Why this could matter in an investigation

Illustrative sequence: repeated authentication failures → a successful connection → an unusually large outbound transfer. Each event may be inconclusive alone; the relationship can make the activity more concerning. Small recurring connections can likewise reveal a beacon-like rhythm across a session.

These are practical motivations for sequence memory, not claims that the saved model has been validated on these exact situations. Sona needs representative training and testing to distinguish malicious behavior from legitimate automation.

What today's memory means: context within one supplied session. The current model makes one prediction for the complete session, which its flows inherit. It does not retain memory between sessions, store long-term host histories, or provide human-like reasoning. Compression can lose evidence, and unfamiliar traffic can still cause false alarms. Broader training and reliable evaluation remain essential.
